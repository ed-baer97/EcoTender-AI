# Demo script — EcoTender AI (≈2 минуты)

Caspian Hackathon 2026 · фокус: **Казахстан / Каспий**

## Подготовка (до выхода на сцену)

```bash
docker compose up -d
python scripts/smoke_check.py
# опционально live explain: ключ в кабинете администратора (LLM) или LLM_API_KEY в .env
```

Открыть: **http://localhost:5173**

Smoke проверяет: gateway `/health`, `/api/v1/ready`, login admin, `/auth/me`, risk по `KZ-ECO-1001`.
---

## Сценарий (120 секунд)

### 0:00–0:20 — Проблема
> «Экологические тендеры Каспия непрозрачны: завышенные цены, один участник, одни и те же подрядчики. EcoTender AI автоматически считает Risk Score и объясняет аудитору почему.»

Показать карту: цветные маркеры (зелёный→красный), чип `KZ`, счётчики risk bands.

### 0:20–0:50 — Тендер №1 (критичный) — кликнуть
**`KZ-ECO-1001` — Очистка береговой линии порта Актау от нефтезагрязнений**

Что сказать:
- сумма vs рынок (+~47%)
- единственный участник
- подрядчик `КаспийЭкоСервис` с высокой долей побед
- Risk Score ~90+ / `critical`
- «CatBoost принял решение, LLM/шаблон объяснил причины»

### 0:50–1:20 — Тендер №2 (критичный, другой паттерн)
**`KZ-ECO-1004` — Рекультивация нефтезагрязнённых участков — Доссор**  
(если нет в списке — любой красный с `single_source` / Атырау)

Что сказать:
- закупка из одного источника
- рост через доп. соглашения
- «система ловит не только overprice, но и процедурные аномалии»

### 1:20–1:45 — Тендер №3 (низкий риск) — контраст
**`KZ-ECO-1002` — Мониторинг качества морской воды — зона Тенгиз**

Что сказать:
- 5 участников, цена ≈ рынок
- Risk Score низкий / `low`
- «мы не красим всех подряд — ранжируем риски для аудита»

### 1:45–2:00 — Архитектура в одном предложении
> «Своя ML-модель (CatBoost) считает риск, LLM API объясняет; данные — PostGIS + парсер goszakup OWS v3; карта Leaflet.»

По желанию мельком: Swagger `http://localhost:8000/docs`, Flower `http://localhost:5555`.
